# 上下文优化技术

上下文优化通过策略性压缩、遮蔽、缓存和分区扩展有效上下文窗口容量。有效优化可使有效上下文容量翻倍或三倍。

## 激活场景

- 上下文限制约束任务复杂度
- 优化成本（更少token = 更低成本）
- 减少长对话延迟
- 实现长时间运行的Agent系统
- 处理更大文档或对话
- 构建规模化生产系统

## 四大优化策略

### 1. Compaction（压缩）

接近限制时摘要上下文内容，用摘要重新初始化新上下文窗口。

**压缩优先级**：
1. 工具输出 → 替换为摘要
2. 旧轮次 → 摘要早期对话
3. 检索文档 → 如有新版本则摘要
4. **永不压缩**系统提示

**摘要保留要点**：
- 工具输出：保留关键发现、指标、结论
- 对话轮次：保留关键决策、承诺、上下文转变
- 检索文档：保留关键事实和声明

### 2. Observation Masking（观察遮蔽）

工具输出可占用80%+的token。遮蔽用紧凑引用替换冗长输出。

**遮蔽策略**：

| 操作 | 场景 |
|------|------|
| 永不遮蔽 | 当前任务关键的观察、最近轮次、活跃推理中使用的 |
| 考虑遮蔽 | 3+轮前的观察、可提取要点的冗长输出、目的已达成的 |
| 总是遮蔽 | 重复输出、样板页眉/页脚、已在对话中摘要的 |

```python
if len(observation) > max_length:
    ref_id = store_observation(observation)
    return f"[Obs:{ref_id} 已省略. 关键: {extract_key(observation)}]"
```

### 3. KV-Cache Optimization（KV缓存优化）

缓存跨请求共享相同前缀的KV张量，避免重新计算。

**优化模式**：
- 稳定元素放前面（系统提示、工具定义）
- 频繁重用元素其次
- 唯一元素放最后

```python
# 缓存友好排序
context = [system_prompt, tool_definitions]  # 可缓存
context += [reused_templates]  # 可重用
context += [unique_content]  # 唯一
```

**提升缓存稳定性**：
- 避免动态内容（如时间戳）
- 使用一致格式
- 跨会话保持结构稳定

### 4. Context Partitioning（上下文分区）

跨具有隔离上下文的子代理分区工作。每个子代理在干净上下文中操作，专注于其子任务。

**结果聚合**：
1. 验证所有分区完成
2. 合并兼容结果
3. 如果仍太大则摘要

## 预算管理

### 上下文预算分配

| 类别 | 说明 |
|------|------|
| 系统提示 | 固定分配 |
| 工具定义 | 固定分配 |
| 检索文档 | 动态分配 |
| 消息历史 | 动态分配 |
| 保留缓冲 | 10-20%预留 |

### 触发式优化

监控信号：
- token利用率超过80%
- 退化指标
- 性能下降

## 优化决策框架

**何时优化**：
- 上下文利用率超过70%
- 对话延长时响应质量下降
- 长上下文导致成本增加
- 对话长度导致延迟增加

**应用什么**：
| 主导组件 | 策略 |
|----------|------|
| 工具输出 | 观察遮蔽 |
| 检索文档 | 摘要或分区 |
| 消息历史 | 带摘要的压缩 |
| 多组件 | 组合策略 |

## 性能目标

| 策略 | 目标 |
|------|------|
| 压缩 | 50-70% token减少，<5%质量下降 |
| 遮蔽 | 60-80%被遮蔽观察减少 |
| 缓存优化 | 70%+稳定工作负载命中率 |

## 关键原则

1. 优化前先测量——了解当前状态
2. 可能时先应用压缩再遮蔽
3. 用一致提示设计缓存稳定性
4. 在上下文变得有问题前分区
5. 随时间监控优化有效性
6. 平衡token节省与质量保留
7. 在生产规模测试优化
8. 为边缘情况实现优雅降级
