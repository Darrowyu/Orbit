# 规格访谈技能

通过深入、探究式的访谈，将草稿规格说明转化为完整的技术文档。

## 概述

阅读 `plan.md` 或者用户指定文档，并使用 `AskUserQuestionTool` 对用户进行详尽的访谈。访谈内容可以涵盖任何方面：技术实现、UI 与 UX、潜在顾虑、权衡取舍等，但请确保提出的问题具有深度，而非显而易见。

请保持深度并持续提问，直到访谈完全结束，最后将完善后的规格说明（spec）写入该文件中。

## 流程

### 1. 准备阶段

- 阅读目标文档（plan.md 或用户指定文档）
- 分析文档结构，识别模糊或缺失的部分
- 准备访谈大纲，按优先级排列问题

### 2. 深度访谈

访谈维度涵盖但不限于：

**技术实现**
- 技术选型的理由和替代方案
- 性能要求和可扩展性考量
- 依赖关系和兼容性约束
- 数据模型和存储方案

**UI/UX 设计**
- 用户交互流程的完整路径
- 异常状态的展示方式
- 加载、空状态、错误状态处理
- 响应式和可访问性要求

**边缘情况**
- 并发操作的处理
- 网络异常的容错机制
- 数据边界和极限值处理
- 用户中断操作的处理

**风险考量**
- 安全性和权限控制
- 数据一致性保障
- 回滚和恢复策略
- 监控和告警机制

**权衡取舍**
- 复杂度 vs 功能完整性
- 开发时间 vs 代码质量
- 性能 vs 可维护性
- 短期交付 vs 长期架构

**架构决策**
- 模块划分和职责边界
- 接口设计和契约定义
- 状态管理策略
- 错误处理和日志规范

### 3. 访谈原则

- **一次一个问题** - 每条消息只问一个深度问题
- **避免显而易见** - 不问文档中已明确说明的内容
- **追问深入** - 对模糊回答继续追问
- **关联上下文** - 结合项目现状提问
- **优先选择题** - 复杂问题提供2-3个选项便于决策

### 4. 完善文档

访谈结束后：

- 整理所有访谈结果
- 将新增的规格说明写入原文档
- 保持文档结构清晰，分节明确
- 标注决策理由和权衡考量

## 示例对话

```
老板：帮我完善这个 plan.md

你：好的，我已阅读了 plan.md。关于用户认证模块，文档提到"支持多种登录方式"，
    但没有说明具体的优先级和降级策略。
    
    如果第三方登录（如微信）服务不可用，你希望：
    A) 仅显示错误提示，隐藏该登录选项
    B) 自动切换到备用登录方式（如手机验证码）
    C) 保留入口但点击时提示稍后重试

老板：B，自动切换

你：明白。那切换到备用方式时，需要给用户明确的提示吗？
    还是静默切换让用户无感知？

老板：需要提示，但不能太打扰

你：好的。关于登录失败的重试策略，文档没有提及。
    你希望限制重试次数吗？如果是，达到限制后的处理方式是：
    A) 锁定账户一段时间
    B) 要求验证码验证
    C) 触发人工审核流程

老板：B，加验证码

你：收到。接下来我想问关于数据存储的问题...
```

## 访谈结束标志

当以下条件满足时，访谈结束：

- 所有模糊点都已明确
- 关键决策都有明确结论
- 边缘情况都有处理方案
- 用户确认没有其他需要补充

访谈结束后，将完善的规格说明写入文档，并询问用户是否需要进入实现阶段。
