# 上下文工程基础

上下文是语言模型推理时可用的完整状态，包括系统指令、工具定义、检索文档、消息历史和工具输出。

## 激活场景

- 设计新Agent系统或修改现有架构
- 调试可能与上下文相关的意外行为
- 优化上下文使用以降低token成本
- 审查上下文相关设计决策

## 核心概念

### 上下文组成

| 组件 | 说明 | 特点 |
|------|------|------|
| 系统提示 | 核心身份、约束、行为准则 | 会话开始加载，全程持久 |
| 工具定义 | Agent可执行的操作 | 位于上下文前端 |
| 检索文档 | 领域知识、参考资料 | 运行时按需拉取 |
| 消息历史 | 对话记录、推理过程 | 可能主导上下文使用 |
| 工具输出 | 操作结果 | 可达83.9%的总上下文 |

### 注意力预算约束

- 语言模型通过注意力机制处理token，n个token产生n²关系
- 随着上下文增长，注意力预算被稀释
- 中间位置信息召回率降低10-40%（U型曲线）

### 渐进式披露原则

- 启动时仅加载skill名称和描述
- 激活时才加载完整内容
- 保持Agent快速同时可按需访问更多上下文

## 实践指导

### 系统提示组织

```markdown
<背景信息>
你是Python专家，帮助开发团队。
当前项目：Python 3.9+ 数据处理管道
</背景信息>

<指令>
- 编写干净、惯用的Python代码
- 函数签名包含类型提示
- 公共函数添加docstring
</指令>

<工具指导>
shell操作用bash，代码任务用python。
文件操作用pathlib确保跨平台兼容。
</工具指导>

<输出描述>
提供带语法高亮的代码块。
在注释中解释非显而易见的决策。
</输出描述>
```

### 上下文预算

- 在70-80%利用率时触发压缩
- 关键信息放在开头和结尾（注意力有利位置）
- 为降级设计，而非期望完美条件

## 关键原则

1. 将上下文视为有限资源，边际收益递减
2. 关键信息放在注意力有利位置（开头和结尾）
3. 使用渐进式披露延迟加载
4. 用清晰的分节边界组织系统提示
5. 开发期间监控上下文使用
6. 优先选择小而高信号的上下文，而非大而低信号的
